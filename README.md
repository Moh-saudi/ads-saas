# منصة مِسك لإدارة اللافتات الذكية

تطبيق SaaS عربي RTL: موقع عام لكل شركة على نطاقها، وشعارها وألوانها وبيانات التواصل، ومساحة إدارة محمية بالمستخدم والدور ونطاق الحي. مبني على Next.js 16 App Router وSupabase/PostgreSQL وPostGIS، ومجهز للنشر على Vercel.

المستودع: [Moh-saudi/ads-saas](https://github.com/Moh-saudi/ads-saas)، الفرع الرئيسي `main`. تُنشأ ملفات البيئة محليًا من `web/.env.example`؛ ملفات `.env.local` ومفاتيح الخدمة وكلمات المرور ليست ضمن المستودع.

الموقع المنشور: [شركة زين للإعلان](https://ads-kappa-one.vercel.app/)، [دخول فريق العمل](https://ads-kappa-one.vercel.app/login). جرى التحقق من الموقع وتسجيل دخول المدير على الإنتاج بعد نشر التصميم الجديد.

## حالة التنفيذ وخطة الاستكمال

## التشغيل والمعاينة

موقع الشركة بتصميم وكالة: هيرو بثلاث شرائح وصور أصلية، تنقل تلقائي ويدوي وإيقاف الحركة، أقسام النبذة والأماكن والأفكار والشركاء ودليل المواقع مع البحث والتصفية، ونموذج طلب مرتبط بكود الأصل. لا تُضاف شركات أو حملات أو أرقام أداء وهمية. الصور الافتراضية تصورات إبداعية؛ [وصف الأصول ومجموعة prompts](web/public/media/agency/README.md).

من **الإعدادات ← تصميم ومحتوى موقع الشركة** يستطيع المدير تعديل الشرائح وترتيبها، رفع صور JPG/PNG/WebP حتى 2MB، وإدارة الأماكن والأعمال وأسماء وشعارات الشركاء ونبذة الشركة. الحفظ معزول بالشركة ومقصور على المدير، والقراءة العامة عبر `public_website` للنطاق المعتمد فقط. يلزم تطبيق migration `20261018105231_agency_website_content.sql` عند ترقية نسخة قديمة.

إعداد اتصال المتصفح العام موجود في `web/config/public-supabase.json` لإتاحة تشغيل مشروع زين على Vercel دون الوقوف عند `/setup`. يحتوي URL ومفتاح **publishable** فقط، وهما إعدادان عامان مخصصان للمتصفح، ولا يحتوي مفتاح خدمة أو كلمة مرور. متغيرات البيئة لها الأولوية عند تخصيص نشر آخر. نطاق `ads-kappa-one.vercel.app` مسجل لشركة زين؛ ويعيد `/setup` التوجيه للموقع إذا اكتمل الربط.

يلزم Node.js 22 أو أحدث.

```powershell
npm ci
npm --prefix web ci
npm run dev
```

- لوحة ببيانات تجريبية معلّمة: `http://localhost:3000/demo/dashboard`
- معاينة موقع عميل: `http://localhost:3000/demo-site`
- إرشادات الربط: `http://localhost:3000/setup`
- الموقع الحقيقي: `/`، الدخول: `/login`، الإدارة: `/app/dashboard`.

المعاينة لا تحفظ بيانات ولا تستبدل نتائج قاعدة البيانات الحقيقية بأرقام تجريبية. جميع عمليات الحفظ تتطلب Supabase وحسابًا مربوطًا بالشركة.

## قاعدة Supabase لأول مرة

المشروع الفعلي: `jdccaknvmenifhipskau`. **مُهيأ لشركة زين للإعلان بحساب مدير `info@zain.io` ومناطق القاهرة الجديدة والشروق وطريق السويس.** طُبقت النواة المجمعة وأحدث التحديثات؛ لا تعِد تشغيل ملف التأسيس على هذا المشروع. التعليمات التالية لتأسيس بيئة جديدة فقط.

1. خذ نسخة احتياطية إذا كانت القاعدة تحتوي بيانات، ولا تُشغّل ملف التأسيس على قاعدة تحتوي الجداول نفسها.
2. لقاعدة فارغة، افتح SQL Editor ونفّذ `supabase_setup.sql`. الملف مولّد من migrations كلها في معاملة واحدة، ولا يضيف شركة أو مستخدمين تجريبيين.
3. إذا كان `0001` منفذًا سابقًا، نفّذ migrations الجديدة فقط بالترتيب أدناه. تحقّق أولًا من مخططك الفعلي وتوافق البيانات مع القيود الجديدة.
4. للبيئة التجريبية فقط نفّذ `supabase/seed.sql`؛ ينشئ شركة `demo` على `localhost` و`127.0.0.1`.
5. أنشئ مستخدمًا من Authentication ثم اربطه في `profiles`، باستخدام UUID الحقيقي للمستخدم. لا تعتمد الصلاحيات على `user_metadata`.

```sql
-- بعد إنشاء المستخدم. استبدل UUID قبل التنفيذ:
insert into public.profiles(id, tenant_id, full_name, role)
values ('AUTH_USER_UUID', '00000000-0000-0000-0000-000000000001', 'مدير الشركة', 'admin');
```

**تنبيه الاستكمال للبيئة الحالية:** سجل المشروع البعيد يحتوي `initial_advertising_saas_baseline` الذي يجمع أول 12 ملفًا، ثم آخر ثلاثة تحديثات. لا تشغّل `supabase db push` قبل مطابقة هذا السجل مع الملفات المحلية؛ لا تُعد تنفيذ الجداول الموجودة.

لفحص الربط المستضاف دون إضافة معاملات أو سجلات أعمال، مرّر `LIVE_TEST_EMAIL` و`LIVE_TEST_PASSWORD` كمتغيرات بيئة مؤقتة ثم شغّل `npm run test:live`. تُقرأ إعدادات المفتاح العام من `web/.env.local`، وتُحفظ نتيجة منقحة دون بيانات دخول في `output/verification/live-integration.json`.

## إعداد التطبيق

انسخ `web/.env.example` إلى `web/.env.local` وأضف:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://jdccaknvmenifhipskau.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLIC_KEY
```

يدعم التطبيق `NEXT_PUBLIC_SUPABASE_ANON_KEY` أيضًا للمفتاح العام القديم. لا تضع `service_role` في أي متغير يبدأ بـ `NEXT_PUBLIC_`. لا يحتاج تطبيق الويب مفتاحًا سريًا.

## النشر على Vercel

ارفع هذا المجلد إلى مستودعك، ثم أنشئ مشروع Vercel منه. **Root Directory = `web`**، والإطار Next.js، وأضف المتغيرين أعلاه إلى بيئات النشر المطلوبة. أمر البناء `npm run build` داخل `web`.

بعد معرفة نطاق النشر المؤقت `your-project.vercel.app`، أضفه إلى `tenant_domains` باسم المضيف فقط، دون بروتوكول أو منفذ، ثم `verified = true` بعد التأكد من أنه نطاقك. جميع النطاقات المجهولة أو غير المعتمدة تُرفض. يُقرأ `Host` مباشرة ويعاد التحقق من شركة المستخدم على الخادم؛ لا يعتمد التفويض على ترويسة `x-tenant-id` من المتصفح.

```sql
insert into public.tenant_domains(domain,tenant_id,verified,is_primary)
values ('your-project.vercel.app','YOUR_TENANT_UUID',true,true);
```

لعميل جديد، أنشئ `tenants` ثم `profiles` و`tenant_modules` ونطاقه. أضف نطاق العميل إلى مشروع Vercel واضبط DNS حسب القيمة التي يعرضها Vercel. تحقّق من ملكية النطاق قبل تفعيل `verified`. يوجد مثال غير تنفيذي في `supabase/onboarding.example.sql`.

من الإعدادات يستطيع مدير الشركة تغيير الشعار والألوان والتواصل ووحدات مساحة العمل. لا يستطيع المستخدم تغيير `tenant_id` أو دوره أو اعتماد نطاق جديد من المتصفح.

## أول تشغيل فعلي

1. أنشئ المحافظة ثم الحي ثم الشارع من المناطق والشوارع.
2. أضف نوع الأصل، ثم الأصل وإحداثياته. النشر في الموقع العام اختيار صريح لكل أصل.
3. أنشئ الطرف المعلن وبقية الأطراف، ومنها الوطنية.
4. أنشئ العقد الصاعد وحدد أصوله وتكلفة كل عنصر الشهرية يدويًا.
5. أنشئ عقد المعلن. يُرفض التداخل أو تجاوز تغطية العقد الصاعد داخل قاعدة البيانات، ويُلغى الحفظ كله عند فشل أي بند.
6. سجّل فواتير التحصيل أو مستحقات الوطنية كفواتير دفع، ثم الدفعات. يمنع النظام تجاوز المبلغ المتبقي. لا يصدر هذا النظام فواتير ضريبية إلكترونية معتمدة.

نموذج `billing_model` محفوظ، لكن لا يُفترض توزيع تكلفة تلقائي قبل حسم طريقة الدفع. إدخال التكاليف يدوي لكل أصل. قيمة عقد المعلن التقديرية تستخدم 30 يومًا للشهر ولا تستبدل جدول الفوترة الفعلي.

## واتساب (تجهيز اختياري)

الكود في `supabase/functions/whatsapp-reminders/index.ts`. لم يُنشر ولم تُرسل رسائل. يستخدم WhatsApp Cloud API الرسمي وقالب تجديد معتمد يحتوي 3 متغيرات: اسم المعلن، مرجع العقد، تاريخ الانتهاء.

قبل التفعيل، جهّز موافقة المستلم ورقمه الدولي، فعّل وحدة `whatsapp`، ثم اضبط أسرار Edge Function: `REMINDER_CRON_SECRET`, `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_RENEWAL_TEMPLATE`, `WHATSAPP_TEMPLATE_LANGUAGE`, `WHATSAPP_GRAPH_VERSION`. استخدم نسخة Graph المدعومة بحساب Meta؛ لا يُثبّت الكود نسخة قد تنتهي صلاحيتها. الأسرار تخص مرسل المنصة المشترك؛ دعم حساب واتساب مستقل لكل عميل يحتاج مخزن أسرار منفصلًا لاحقًا.

انشر الدالة ثم شغّلها عبر Supabase Cron بطلب POST يومي مع ترويسة `x-cron-secret` وسر محفوظ في Vault. [التوثيق الرسمي للجدولة](https://supabase.com/docs/guides/functions/schedule-functions). تدرج التذكيرات عند بقاء 60/30/7 يومًا حسب توقيت الشركة، بقيد يمنع تكرار إدراج التذكير نفسه. اقرأ `supabase/schedule-reminders.example.sql` قبل تشغيل الجدولة؛ المثال لا يعمل حتى تُنشأ الأسرار.

لا تعاد محاولة الرسائل ذات نتيجة إرسال غير مؤكدة تلقائيًا. راجع `processing` و`uncertain` مع Meta يدويًا قبل إعادة إرسال أي رسالة. تشمل النسخة تذكيرات التجديد وصندوق مراقبتها؛ إشعارات العقود الجديدة ليست مفعلة.

## الاختبارات والحدود

```powershell
npm run test:db
npm run typecheck
npm run build
```

اختبار القاعدة يستخدم PostgreSQL داخل PGlite مع PostGIS وbtree_gist وpgcrypto، وينفّذ migrations التطبيق نفسها. يُحاكي فقط جداول Auth وStorage المملوكة للمنصة؛ لا يغني عن اختبار تكامل على مشروع Supabase تجريبي. لا يحتاج Docker أو اتصالًا بقاعدة إنتاج.

الحجز يمنع التداخل حتى في الطلبات المتزامنة بواسطة Exclusion constraint، وتستخدم عمليات العقود قفلًا لكل شركة. اختبار PGlite لا يحاكي اتصالات متعددة. تُفحص التغطية حاليًا بفترة صاعدة واحدة متصلة لكل بند. تُحمّل المجموعات في صفحات من 500 صف حتى 20 ألف سجل للمجموعة، ثم يظهر تنبيه يطلب تضييق التقرير. عرض مجموعات الشركات الكبيرة يحتاج ترقيمًا وتصفية على الخادم لكل شاشة لتقليل النقل والذاكرة؛ الحد لا يُخفي بيانات بصمت. الخرائط تحتاج اتصال OpenStreetMap بالإنترنت. PWA يوفر التثبيت وصفحة انقطاع الاتصال فقط، ولا يخزن بيانات الشركات أو يدعم الكتابة دون اتصال.

حدود النسخة الحالية: الاشتراكات المدفوعة وإدارة عملاء المنصة ذاتيًا وبوابة دخول منفصلة للمعلن لم تنفذ. لا يوجد ربط حكومي للفواتير الإلكترونية، أو ضرائب وتأمينات رواتب تلقائية، أو مرفقات ومستندات العقود، أو تسويات بنكية مع كشف مستورد، أو ميزانية عمومية وإقفال سنوات محاسبية. الإهلاك إداري تقديري ولا يُرحّل تلقائيًا. استلام الشراء كامل مرة واحدة؛ الاستلام الجزئي والمرتجعات إلى المورد لم تنفذ. التراخيص سجل وانتهاء وتنبيه، دون تكامل مع الجهة المصدرة. إنشاء حسابات المستخدمين ومنح أدوارهم واعتماد نطاقات الشركات يحتاج مشغل منصة موثوق حاليًا. هذه البنود مسجلة كمرحلة لاحقة في ملف الخطة؛ ليست مزايا مكتملة.

المراجع: [Supabase SSR](https://supabase.com/docs/guides/auth/server-side/creating-a-client?framework=nextjs)، [Supabase MCP](https://supabase.com/docs/guides/ai-tools/mcp)، [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)، [Vercel Domains](https://vercel.com/docs/domains/working-with-domains/add-a-domain).


## تشغيل نسخة main الحالية دون تنزيل الخطوط

خطوط Cairo وTajawal وInter مضمّنة في `web/app/fonts` مع تراخيص OFL ومصدر مثبت وبصمات SHA256، ويستخدمها `next/font/local`. تبقى هوية الموقع وخطوط لوحة التحكم والأرقام الإنجليزية كما في نسخة GitHub الحالية، دون اعتماد البناء على Google Fonts.

شغّل `npm run test:db` ثم `npm run build` ثم `npm run typecheck`. صفحات `/demo/dashboard` و`/demo-site` و`/demo-invoice/f1` تعرض بيانات تجريبية مع تعطيل الحفظ، ويمكن فحصها دون الاتصال بالمشروع المستضاف. التشغيل الفعلي يبقى خاضعًا للنطاق المعتمد والمصادقة والصلاحيات.

يحترم محرر الموقع قائمة أماكن فارغة محفوظة، وتُستخدم صورة توضيحية بديلة إذا لم يتوفر رابط صورة المكان. لون الشركة يطبّق على أزرار الموقع الأساسية مع بقاء اللمسات التحريرية للتصميم.


## إضافة أصل من الخريطة

من الأصول ← إضافة أصل، اختر الشارع ونوع الأصل ثم اضغط موقع اللوحة على خريطة OpenStreetMap. يمكن تكبير الخريطة وسحب العلامة، أو استخدام موقع الجهاز بعد السماح للمتصفح؛ راجع الدقة التقريبية قبل الحفظ. يدعم النموذج أيضًا الانتقال إلى خط عرض وطول معروفين. لا يُحفظ الموقع الافتراضي للخريطة؛ يلزم اختيار نقطة، ويُرفض الطلب في الخادم عند غياب إحداثيات صحيحة.

الإحداثيات معروضة للقراءة وتُحفظ في عمود PostGIS الموجود. اختيار النقطة لا يثبت حدود الحي أو يختار الشارع تلقائيًا؛ راجع تطابقه مع الشارع المسجل. يتطلب تحديد موقع الجهاز HTTPS أو localhost وإذن المستخدم. تحميل تفاصيل الخرائط يحتاج السماح بالاتصال بـ `tile.openstreetmap.org`؛ يظهر تنبيه عند فشل التحميل.


## صور الأصول وتحديث الموقع الدقيق

يمكن اختيار صورة أولية مع نموذج إنشاء الأصل، وإضافة صور أخرى من بطاقة الأصل. الصور بصيغ PNG/JPEG/WebP حتى 2 ميجابايت لكل صورة، وتُحفظ في bucket خاص `asset-photos`؛ لا تُنشر تلقائيًا في الموقع العام. العرض بروابط مؤقتة لمدة 5 دقائق، مع زر تحديث المعرض عند انتهاء الرابط. الرفع والحذف للأدوار المخولة بالأصل، والقراءة تتبع الشركة والمنطقة.

من بطاقة الأصل يمكن فتح «ضبط الموقع الدقيق على الخريطة»، واختيار النقطة وتسجيل سبب التصحيح. تظهر مؤشرات المواقع المحددة وغير المحددة في لوحة القيادة وقسم الأصول، دون اعتبار موقع غائب إحداثيات صفرية. تقارير المناطق تعتمد الشارع المسجل، ولا تُستنتج الحدود الإدارية تلقائيًا من النقطة.

لتفعيل هذه الإضافة على قاعدة قائمة، راجع سجل migrations وطبّق الترقية الجديدة فقط `supabase/migrations/20261018164000_asset_photos_and_location.sql` بعد الترقيات الست عشرة الموجودة. لا تُعد تشغيل `supabase_setup.sql` على قاعدة قائمة؛ الملف المجمع أصبح يشمل 17 migration وهو مخصص لقاعدة جديدة. لم يُنفذ اختبار Storage API مستضاف أو كتابة على قاعدة الإنتاج في هذه الجلسة.

## دليل بدء تشغيل مشروع الإعلانات

من القائمة اختر **دليل بدء التشغيل** (`/app/guide`)، أو افتح المثال دون تسجيل دخول عبر `/demo/guide`. يعرض الدليل عشر خطوات بأسماء الشاشات والحقول والمسؤول عن كل مرحلة، مع مثال لثلاثة أصول وعقد استغلال ومشتريات وحملة إعلانية وحساب هامش. المتابعة مؤقتة للصفحة، ولا تنشئ سجلات في قاعدة الشركة. يوضح الدليل حدود النظام الحالية، ومنها عدم الربط التلقائي لتاريخ تصريح الأصل بعقد المعلن، والحاجة إلى استكمال التصنيع وقائمة الأسعار وتقارير الربحية التاريخية.

داخل دليل بدء التشغيل يوجد زر **ابدأ الجولة التفاعلية**. ينقل المستخدم عبر 12 مرحلة في الشاشات الفعلية، مع التالي والسابق والإغلاق، وإبراز زر الإضافة وفتح النموذج وفق الصلاحيات. لا تنفّذ الجولة حفظًا أو إنشاء سجلات؛ «التالي» انتقال تعليمي فقط. رابط المرحلة يحفظ موضع الجولة في عنوان الصفحة، وتعمل الجولة أيضًا في الديمو مع تعطيل الحفظ المعتاد.

# طرق التحصيل والدفع

اختيار يدوي إلزامي للدفعات الجديدة: نقدي، تحويل بنكي، إنستا باي، فودافون كاش، بطاقة بنكية، أو أخرى. طريقة العملية مستقلة عن الحساب المستلم، ولا تتصل ببوابة دفع. يضيف migration رقم 18 حقلًا افتراضيًا unknown للدفعات والحركات، مع دالتين تحافظان على فحوص عمليات الفوترة والنقدية الأصلية وتخزين الطريقة في نفس المعاملة. الواجهات القديمة تبقى متاحة وتنتج طريقة غير محددة، ولا تُخمّن طريقة السجلات التاريخية.

الرسم في الفواتير والتحصيلات ولوحة المتابعة والتقارير يجمع receipt وincome فقط مرة واحدة من دفتر النقدية، ويستبعد التحويلات والأرصدة الافتتاحية والمصروفات والمدفوعات والرواتب. يحترم الفترة وتاريخ اليوم بالقاهرة، وتظهر الطرق المسجلة في دفتر الخزينة وقائمة دفعات الفاتورة. ديمو الشهر الحالي: 4,000 نقدي + 5,000 تحويل بنكي + 3,000 إنستا باي + 3,500 فودافون كاش + 2,500 بطاقة = 18,000 ج.م، مع حسابات استلام وقيود متوازنة.

التحقق: 176 فحص قاعدة بيانات محلي ناجح في PGlite/PostGIS (Auth وStorage مخططان بديلان)، تشمل منع الزيادة وعزل الشركة والصلاحيات وحفظ الطريقة وتوازن القيد للإيراد المباشر، والتوافق مع API القديم، والحدود الزمنية واستبعاد غير التحصيل. نجح test:demo وبناء الإنتاج وTypeScript. أصلح الاختبار القديم للتذكير بضبط جلسة الاختبار على توقيت القاهرة، بما يوافق يوم الشركة بدل UTC. Chromium على 1440 و390: خمس طرق وإجمالي 18,000، ظهور غير المحدد عند توسيع الفترة، إلزام الاختيار، عرض الطريقة بالخزينة وخمس دفعات بالفاتورة، دون تجاوز أفقي للرسم.

التفعيل المستضاف لم ينفذه المساعد: تشغيل `supabase/migrations/20261019093000_collection_methods.sql` فقط مرة واحدة في SQL Editor بعد الترقيات السابقة. لا يعاد تشغيل bundle على قاعدة قائمة. لم تُختبر كتابة دفع فعلي على الإنتاج.

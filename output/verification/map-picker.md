# اختيار موقع الأصل من خريطة تفاعلية

18 أكتوبر 2026 — مبني على نسخة main المعتمدة وإصلاحاتها المحلية الحالية.

- Leaflet/OpenStreetMap داخل نموذج إنشاء الأصل: الضغط يثبت نقطة واحدة، والسحب يغيّرها، وطلب GPS اختياري مع عرض دقته التقريبية. فشل GPS أو رفض الإذن لا يمحو نقطة سبق اختيارها. نتيجة GPS متأخرة لا تستبدل اختيارًا يدويًا أحدث.
- الانتقال لإحداثيات معروفة، عرض قيم latitude/longitude للقراءة، ومسح وإعادة اختيار النقطة. النموذج يبدأ دون نقطة؛ لا يُرسل مركز افتراضي. بعد نجاح الحفظ تُمسح النقطة مع إعادة ضبط النموذج.
- الخادم يرفض الإحداثيات الناقصة وغير المحدودة وخارج المجال. التخزين في geom الموجود باستخدام SRID=4326 وlongitude قبل latitude. لا schema/migration جديدة، ولا تغيير في صلاحيات الشركة والمنطقة.
- يبقى الشارع اختيارًا صريحًا من بيانات الشركة؛ لا توجد خدمة بحث عناوين أو reverse-geocoding ولا إثبات آلي لحدود الحي.
- خرائط العرض والاختيار تستخدم المصدر نفسه `tile.openstreetmap.org` مع نسب المصدر إلى OpenStreetMap. لم تُرسل كتابة إلى Supabase أو بيانات إنتاج.

## التحقق

- `npm run test:db`: 148 فحصًا محليًا ناجحًا، منها رفض الإحداثيات الغائبة/غير الصالحة وقبول الصفر، وإدخال النقطة عبر دالة التنسيق المستخدمة في التطبيق ثم التحقق من ST_X/ST_Y داخل PostGIS. Auth/Storage مخططات بديلة في الاختبار.
- `npm run build` و`npm run typecheck`: ناجحان.
- Chromium بعرضي 1440 و390: اختيار النقطة وتعبئة FormData، الانتقال لإحداثيات، محاكاة GPS الناجح والمرفوض والمتأخر، المسح، إعادة فتح النموذج، تعطيل الحفظ التجريبي، وعدم تجاوز عرض الصفحة. سحب العلامة تحقق فعليًا بالماوس على 1440. التفاصيل في map-picker-browser.json.
- بلاطات الخرائط حُجبت أثناء اختبار التفاعل؛ الاختبار يثبت منطق Leaflet والنموذج ولا يثبت تحميل خرائط العالم الفعلية. فشل طلب البلاطة المباشر في البيئة بـ CONNECT 403. حُفظت إضافة tile.openstreetmap.org إلى allowed_domains مع الحفاظ على نطاق Supabase؛ يلزم مراجعة الإعدادات وحفظها ونشر البيئة لتفعيلها. GPS الحقيقي يحتاج جهاز المستخدم وإذنه وHTTPS/localhost؛ الاختبار حاكى callbacks فقط.

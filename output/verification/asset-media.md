# صور الأصول والموقع الدقيق وإحصائيات التغطية

18 أكتوبر 2026. تطوير فوق main المعتمد مع الإصلاحات المحلية السابقة.

## ما تغير

- صورة اختيارية مع إنشاء الأصل، وصور إضافية عبر معرض بطاقة الأصل؛ تحقق من المحتوى الفعلي وحد 2MB للصورة، وأسماء UUID دون overwrite. الصورة غير الصالحة تُرفض قبل إنشاء الأصل. إذا فشل التخزين بعد إنشاء الأصل، توضح النتيجة أن الأصل أُنشئ مع موقعه وتطلب إعادة رفع الصورة من بطاقته فقط، لتجنب تكرار الأصل.
- تخزين خاص في asset-photos؛ سياسات القراءة والرفع والحذف مرتبطة بالأصل وشركته ومنطقة المستخدم والوحدة المفعلة. لا روابط عامة، ولا نشر تلقائي للصور عند تفعيل public_visible. روابط العرض موقعة لمدة 5 دقائق ويمكن تحديث المعرض.
- تعديل إحداثيات أصل موجود بعملية RPC تتحقق من الصلاحية والمجال والسبب، وتحدث geom فقط وتسجل الإحداثيات السابقة والجديدة وسبب التغيير في audit_events. الواجهة تعرض الإحداثيات بدقة 7 منازل عشرية؛ ذلك دقة تمثيل وليس ضمانًا لدقة GPS الميدانية.
- مؤشرات مستقلة للمواقع المحددة وغير المحددة والتغطية، تستبعد الأصول المستبعدة وتتعامل مع (0,0) كنقطة صالحة صريحة. خريطة الأصول تتجاهل القيم غير الصالحة. تجميع المناطق يتبع معرف منطقة الشارع بدل مطابقة الاسم، لتجنب خلط مناطق متشابهة الأسماء. لا reverse geocoding أو استنتاج حدود إدارية من النقطة.

## التحقق

- `npm run test:db`: **168 فحصًا محليًا ناجحًا**. تشمل content validation الفعلي لملف File وطلب upload عبر مساعد التطبيق بمسار فريد وخيارات MIME/no-overwrite، وعزل الشركات والمناطق، وصلاحيات viewer، ومنع نقل الصور، وخصوصية bucket، ومنع anon، وتعطيل الوحدة، والتحقق من تصحيح الإحداثيات عبر v_asset_register وسبب المراجعة، ومؤشرات التغطية.
- اختبارات SQL في PGlite/PostGIS؛ مخططات Auth وStorage بديلة. طلب upload في اختبار المساعد موك مضبوط، وليس اتصالًا فعليًا بخدمة Storage.
- بناء الإنتاج وTypeScript ناجحان.
- Chromium على 1440px و390px: مؤشرات التغطية، ملف PNG فعلي صغير داخل FormData الإنشاء مع النقطة المختارة، تعطيل الحفظ التجريبي، قسم الصور، وتحرير موقع أصل مع علامته الحالية واشتراط سبب، دون تجاوز أفقي. التفاصيل في asset-media-browser.json.
- بقيت بلاطات OSM محجوبة في اختبار المتصفح؛ لم يُختبر رفع/عرض/حذف صورة عبر Supabase المستضاف ولم تنشأ معاملات أو أصول على الإنتاج.

## التفعيل المتبقي

أكد المستخدم تنفيذ SQL الخاص بالصور والإحداثيات في محرر Supabase وظهور `Success. No rows returned`. هذا تأكيد تنفيذ من المستخدم، وليس فحص تكامل مستضاف أجراه المساعد. لا حاجة لإعادة تشغيل التحديث؛ تبقى خطوة نشر كود التطبيق والتحقق من الرفع والعرض والحذف بحساب فعلي.

الملفات تضم الآن 17 migration. يجب مراجعة السجل المستضاف وتطبيق `20261018164000_asset_photos_and_location.sql` فقط بعد النسخة ذات 16 migration، ثم اختبار الكتابة على بيئة اختبار مستقلة بحسابات الأدوار الفعلية. لا تعِد تشغيل bundle على القاعدة القائمة. تحميل الخريطة يحتاج السماح بـ tile.openstreetmap.org المحفوظ في مسودة شبكة البيئة، ثم حفظ ونشر البيئة لتطبيقه. لم تُرفع الإصلاحات إلى GitHub أو تُنشر على Vercel في هذه الجلسة.
